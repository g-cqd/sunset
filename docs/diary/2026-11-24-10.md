# 2026-11-24 — 10: the CSV import and export, tested hard (roadmap 0095 D)

The owner: the imports and exports are to be thoroughly tested, with the family's own packages (AemiJSON, the HTML and XML ones) where they fit.

| Claim | Probe | Verdict |
|---|---|---|
| What is written as CSV is read back, for any cell | `CSVPropertyTests` (4 properties, 600 / 400 / 300 / 200 generated tables, shrunk by AemiTestKit's `forAll`): quotes, commas, `\r`, `\n`, `\r\n`, tabs, formula starts, an apostrophe, accents, emoji, Cyrillic | **Red first, three failures, two real bugs.** (1) `SunsetStorage.CSV.cell` tested characters, and `"\r\n"` is one `Character` in Swift, so a cell holding CRLF was written unquoted and split its row (the shipped history export too); the formula guard missed a CRLF at the start for the same reason. Fixed by comparing unicode scalars. (2) CSVCoder's parser dropped the empty last field of data that ends on a delimiter with no line ending (`"b ,"` was one cell). Fixed upstream with its test (g-cqd/CSVCoder 317c6cc, 552f750; its 299 + 16 tests pass on macOS); Sunset pinned to it. My own test made the grapheme mistake too, and was fixed the same way. |
| An export imported again returns every field | `LoginRoundTripTests`: 500 generated lists of logins with the awkward characters in title, username, password, note, address and code | **Red: the importer trimmed titles, usernames and notes** (a username `ada ` or a note ending in a newline came back changed; the password was exact). Cells are the person's: only what is a token (address, code, flags, an item's kind) is now trimmed. Green. |
| A hostile or damaged file cannot stop the app | `LoginImportFuzzTests`: 4,000 byte-mutated exports of 40 logins (AemiTestKit `fuzzNeverTraps`, 1 to 12 edits), the file cut at every 7th length, 800 arbitrary byte strings; `LoginImportHostileTests` (10): a 2,000,000-character cell, a million unbalanced quotes, 20,000 logins, a 5,000-column header, ragged rows, a repeated header, NUL and control characters, addresses that are not addresses (`javascript:`, `file:`), header-only, blank and comma-only files, a byte-order mark | All pass. Invariants checked on everything read: only Login-template entries, never more entries than rows, never many more than the file had. Not vacuous: more than half the mutants are still read (the test says how many). |
| Our CSV is CSV to someone else | `CSVPythonOracleTests` + `PythonCSV`: Python 3.15's `csv` run as a process; tables travel as JSON through **AemiJSON** both ways; 12 batches of up to 40 tables each, both directions, and a known-answer test of the harness | Both directions agree. The batch goes through one process, not one per case. Skipped where Python is not installed. |
| These tests can fail | The writer broken on purpose (a bare `\r` no longer quotes), then restored | Four properties failed on it, the Python oracle among them; restored, all pass. |

## Not done yet
- XML: the family has none, on purpose (AemiHMMML's plan: XML's entity and DTD surface "deserves its own security design", "a separate package if ever"); AemiHTML is the WHATWG HTML parser and cannot read XML (it does not honour `<Entry/>`, it folds case). KDBX's inner document needs an XML reader: the owner's call whether to start `AemiXML` first.
- Zip (1PUX): no family package; Sunset's `Inflater` is in the core. Not started.
- The same standard for the formats still to come (Bitwarden JSON on AemiJSON, the OTP apps' files, KDBX, the backup file).
- Mutation testing of the import and export code (litmus, in the background or on a pull request, ADR-0126): not run.
- The header names of the CSV sources are from memory of those exports, not from real files; the oracle checks CSV, not the sources' columns.
