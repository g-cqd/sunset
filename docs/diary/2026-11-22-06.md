# 2026-11-22 — 06: what WebKit tells and lets an app do of a page's media (roadmap 0114)

For the Now Playing cards and picture in picture (the owner's notes of 2026-11-22). Probed with a page playing a generated
video and a sound (ffmpeg's test source and a sine), its `mediaSession` metadata and action handlers set; run under
`swift test` (a bare executable or an ad hoc app in `/tmp` could not start WebKit's GPU process here). Private calls by
name, as `SunsetPrivate` makes them.

| Claim | Probe | Verdict |
|---|---|---|
| Whether a page plays sound is known, and observed | `_isPlayingAudio`, KVO | holds: 0 → 1 → 0 with play and pause; KVO fires |
| Whether a page has a now-playing session is known, and observed | `_hasActiveNowPlayingSession`, KVO | holds; it stays true once paused |
| `requestMediaPlaybackState` says what plays | the public call | does not hold: "playing" before anything played |
| The session's title, artist, duration and elapsed time per page | `_nowPlayingMediaTitleAndArtist:`, `_requestActiveNowPlayingSessionInfo:` | holds for the process only: one session, the page that started playing last; both pages answer the same |
| A page's metadata and media, per page, without touching the page | Sunset's content world reads `navigator.mediaSession.metadata` (title, artwork), `playbackState`, each `video`/`audio` (paused, time, duration, muted) | holds |
| The metadata observer tells changes | `_setNowPlayingMetadataObserver:` | does not hold: never called |
| Play and pause go through the page's own handlers | `_pauseNowPlayingMediaSession:`, `_playPredominantOrNowPlayingMediaSession:` | holds: the page's `pause` and `play` handlers ran |
| A page is muted and unmuted | `_setPageMuted:` with an integer (by its implementation, not `perform(_:with:)`, which passes a pointer) | holds: `_mediaMutedState` 1, then 0 |
| Previous and next reach the page's handlers | `MRMediaRemoteSendCommand` (MediaRemote) 4 and 5 | holds while Sunset is the system's now-playing app |
| … when another app started playing after the page | a near-silent helper with `MPRemoteCommandCenter` started after the page | does not hold: the other app got next and previous |
| `play()` again from Sunset's world takes the system's now playing back | the same | does not hold |
| `pause()` then `play()` from Sunset's world takes it back | the same | holds: next then reached the page |
| Which app is now playing can be asked | `MRMediaRemoteGetNowPlayingApplicationPID` | does not hold: 0 (refused to apps without Apple's entitlement) |
| Seeking from Sunset's world | `currentTime += 10` in its world | holds |
| Picture in picture can be toggled | `_canTogglePictureInPicture` with `_allowsPictureInPictureMediaPlayback` on | not yet: false in a window that is not shown; toggling would open a window on the owner's screen, not tried |

So: previous and next first pause and play the card's media from Sunset's world (a gap of a moment), then send the
command; an app that starts playing in that instant would still get it. Sunset WebKit could take a patch that sends the
action to one page.
