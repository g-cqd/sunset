# 2026-11-25 — 04: Urgent profile-isolation audit and fixes across Spaces, tabs, Favorites, Pinned grids, popups, and extensions

Owner reported being signed into an account from another profile inside a Space that does not belong to that profile, and asked for heavy regression testing on every finding.

| Finding | Root cause | Fix & regression test |
|---|---|---|
| 1. **Move to Space** (`TabsModel.move(rows:to:)`) leaked live web pages across profiles | Moved live `WebContent` (still attached to the source profile's `WKWebsiteDataStore`) straight into the target Space without checking `space.profile` or restarting web panes; also dropped unloaded `pending` descriptors | Checks `sourceProfile != other.space.profile`, extracts both live `contents` and `pending`, calls `other.restart(kind: "web", panes: movedPanes, by: self)`, strips stale `"as"` Reload-As overrides. Verified by `ProfileIsolationRegressionTests` (red first -> green) and real-WebKit `ProfileWebCookieIsolationTests`. |
| 2. **Cross-window drag** (`TabsModel.bringDraggedHere()`) used the wrong profile check | Compared `origin.space.favorites !== space.favorites` instead of `space.profile`. With the default `spaces.favorites == .space` (each Space owns its own `FavoritesModel`), same-profile Spaces needlessly reloaded and cross-profile logic was coupled to Favorites identity; also dropped unloaded `pending` descriptors | Compares `origin.space.space.profile == space.space.profile` when `spaces != nil` (falling back to `favorites ===` for standalone test harnesses); extracts pending descriptors too. Verified by `ProfileIsolationRegressionTests` & `ProfileWebCookieIsolationTests`. |
| 3. **Deleting a Space into a neighbour** (`SpacesModel.remove(_:movingTo:)`) leaked both tabs and Space-owned Favorites | Transferred live `WebContent` tabs and open Space-owned Favorites to `target` without restarting when `space.space.profile != target.space.profile` | Calls `space.restart(kind: "web", by: nil)` before `giveAll()` and `giveFavorites(of:to:)` when crossing profiles. Verified by `ProfileIsolationLifecycleTests`. |
| 4. **Changing a Space's profile or removing a profile** left Space-owned open Favorites on the old profile | `SpaceModel.restart(kind:)` only restarted `space.contents` (tabs), ignoring `space.favorites` when `space.ownsFavorites == true` (the default!) | Added `FavoritesModel.restart(kind:)` called by `SpaceModel.restart(kind:)` when `only == nil && ownsFavorites`, unloading open non-private web Favorites and clearing stale `"as"` overrides. Verified by `ProfileIsolationLifecycleTests` & `ProfileWebCookieIsolationTests`. |
| 5. **App-shared Pinned grid** (`spaces.pinned == .app`) leaked live web pages across profiles | One `FavoritesModel` is shared across profiles; opening/releasing/favoriting a pinned web tab from Personal while in Work kept Personal's live `WebContent` | Tracked `FavoritesModel.openedProfile` per entry; `select(entry:)`, `release(entry:)`, `favorite(pinned:)`, and `move(_:into:at:)` unload foreign-profile web entries so they reopen under the active Space's profile. Verified by `ProfileIsolationLifecycleTests`. |
| 6. **`TabsModel.join(_:)`** moved live web tabs across profiles without restarting | Moved `space.give(to: self)` contents into `other` without checking `space.profile != other.space.profile` | Restarts moved web panes on profile mismatch. Verified by `ProfileIsolationRegressionTests`. |
| 7. **Incoming peek links, standalone-tab `newTab`, popup-to-Space move, and window handoff** leaked or dropped profile | `AppActions.open(pages:)` `.peek` built `WebContent` with `profile == nil`; `AppActions.newTab` built handoff page with `profile == nil`; `PopupWindowStore.move` and `TerminalScene.startOnSpace` adopted handoff `WebContent` into a Space of a different profile | Peek links and standalone `newTab` inherit the acting window's profile; `PopupWindowStore.move` and `TerminalScene.startOnSpace` reload non-private web pages when the destination Space's profile differs. |
| 8. **Extensions (`AppExtensionWindows` & `ExtensionHost`)** cached stale profile and missed `defaultWebsiteDataStore` | `AppExtensionWindows` cached `ExtensionWindow(profile:)` once per `NSWindow`, so switching Spaces across profiles kept the first profile forever; `ExtensionHost` left `WKWebExtensionController.Configuration.defaultWebsiteDataStore` unset (falling back to `.default()`, especially broken on Sunset WebKit builds where `VariantStore` derives per-variant UUIDs) | `ExtensionWindow` now resolves `profile` dynamically via closure; `ExtensionHost` sets `configuration.defaultWebsiteDataStore = VariantStore.store(for: profile)`. Verified by `ProfileWebCookieIsolationTests`. |
