# 2026-11-19 (8): ad blocking's cost and other lists (note n58, task t109)

The owner (n58): "i'd like that we allow using other list for the ad blocking, but i also suspect our performances regarding
ad blocking are very shitty". Release builds; probes in `docs/research/probes/blocking*/`, run on copies of the lists Sunset
keeps (EasyList 77,847 lines, EasyPrivacy 57,499).

| Claim | Probe | Verdict |
|---|---|---|
| The lists are compiled once and kept | `AppBlocking.refresh`, `ContentBlocker.load` read | No: at every launch and every six hours, every list is converted, encoded and compiled again, changed or not; no look-up of the compiled list WebKit keeps. Pages loaded before it ends have no blocking |
| That work is off the main thread | The same | No: `ContentBlocker` is `@MainActor`; conversion and JSON encoding run on it |
| What it costs | `blocking/run.sh`, 5 runs | EasyList: convert p50 309 ms, encode 160 ms (both on the main actor), WebKit compile 1,531 ms. EasyPrivacy: 162, 138, 1,329 ms. So about 0.77 s of the main thread and 2.9 s of compiling at each launch and each six hours. Looking up a compiled list: under 1 ms |
| The lists slow pages | `blocking-page/main.swift`: local pages (no network), 10 loads per condition after one warm-up | 4,000 elements: no list p50 27.2 ms, EasyPrivacy 27.0, EasyList 45.6 (+68%), both 45.5. 10 elements: 1.5 → 9.1 ms. 20,000 elements: 132.9 → 193.1 ms. A fixed ~7.6 ms per document (each frame is one) plus ~3 ms per 1,000 elements, all from EasyList |
| Where EasyList's cost is | The same, EasyList without its generic hiding rules (no `if-domain`) | 137 rules holding 13,638 selectors are the whole cost: without them, 1.7 ms (10 elements), 27.2 ms (4,000), as with no list. The 10,524 site-specific hiding rules cost nothing measurable on other sites |
| A forced style recalculation shows the cost | A class toggled on `<html>`, layout read | 0.0 ms in every condition: WebKit invalidates only what selectors depend on. Not a measure of anything |
| Other lists convert | `blocking-lists/main.swift` on six lists fetched today | Peter Lowe 3,568 rules, compiled 60 ms. Fanboy's Annoyance 22,912 (18,758 hiding; 4,294 left out), 1,620 ms. uBlock filters 2,378 kept, 3,631 left out (its own syntax, scriptlets). OISD big: stopped at WebKit's 150,000 limit, 81,588 left out. **AdGuard Base: refused whole** (WKErrorDomain 6): one site regex (`/^kiryuu0\d+\.com/`) written into a pattern WebKit rejects drops all 108,528 rules. **StevenBlack hosts: refused whole**: its `#` comment lines read as element hiding (selectors like `### Version Information #`), and `0.0.0.0 host` lines are not read as hosts |
| Safari pays the same for hiding | — | Not measured: the cost is WebKit's matching of the selectors given, so any blocker giving EasyList's generic hiding to Safari would pay it (a claim) |
