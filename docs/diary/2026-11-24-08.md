# 2026-11-24 — 08: Logins from a CSV file into the vault (roadmap 0095 D, in)

| Claim | Probe | Verdict |
|---|---|---|
| The family already has a CSV reader, so Sunset need not write one (the owner: "there is a CSVCoder on g-cqd") | `g-cqd/CSVCoder` read; a scratch package in the VM depending on it by revision; its `CSVParser` run on the cases of `CSVReaderTests` | `CSVParser` (raw rows, quotes, doubled quotes, line breaks, CRLF/LF/CR, an unclosed quote) meets every case but two, which a thin `CSVReader` takes: it keeps a byte-order mark in the first cell, and gives a blank line as a row of one empty cell. Resolved graph of a package depending on it: aemi (the revision Sunset pins already), swift-syntax, swift-system, swift-collections, swift-crypto: no Google benchmark package (SwiftPM prunes it), so ADR-0002 holds. CSVCoder's own build, swift-syntax included, took 50 s on the VM. Pinned in `Package.swift` at 1709f6d. |
| The tests of the reader are red for the right reason | `CSVReaderTests` before `CSVReader` | Red: "cannot find 'CSVReader'". Green with the wrapper (4 tests). |
| Columns found by header, per source | `LoginImportTests` (8) and `LoginImportReportTests` (1) before `LoginImport` | Red: "cannot find 'LoginImport'". Green: Apple Passwords (Title, URL, Username, Password, Notes, OTPAuth), Chrome (name, url, username, password, note), Firefox (no title: the site names it), Bitwarden (the first of several addresses, folder, favourite, a bare secret made a code, notes and cards not logins), 1Password (tags, archived), rows with nothing, a code that cannot be read (login kept, said), a file with no password column refused, duplicates against the vault and the file, a cell that begins with `=` kept as written. **The header names are from memory of those exports, not from files checked**; a header is matched without case or punctuation, so a near name still works, and the source name shown is a guess from the columns. A wrong guess changes only the words in the confirmation. Two of my own tests were wrong, not the code (a Base32-valid "unreadable" code; two logins that were duplicates by the site rule). |
| An import is kept entry by entry and that is fast enough | `PasswordsSpeedProbe`, release, 2,000 logins | Reading the file 6.2 ms; keeping them in the vault 1,071 ms (0.54 ms each; a single save is 0.59 ms p50). It runs on the main thread: a 10,000-login file would take about 5 s there, **not measured**, and the list insertion is linear per entry. |
| It can be used | `PasswordsImport`: an open panel, a confirmation with the counts and the warning that the file is in the clear, the import, a result with Show File in Finder | **Not seen on screen.** Built, and its model and wording tested; the panel and the alerts are AppKit's own. The file is never read beyond 64 MiB, only as UTF-8, and left where it is. |
