## First code: the VT parser (ADR-0023)

Package created (`SunsetCore`, strict settings, TerminalKit's formatter and lint configs). Tests first against an empty parser (red, for the right reason), then the state machine in five small files. One compile detour: a one-byte `Span` cannot be returned from a method (`~Escapable`), and an array for it would allocate; a `withUnsafePointer` closure does neither. Properties (split invariance, balanced strings, limits) pass; sabotaging the parser showed they miss a bug that is the same whole and cut (a stale truncation flag), so a directed test was added. Baseline: ASCII 11 M instructions per MiB, CSI-dense ~80 M, all with 0 mallocs.

Owner: Sunset may depend on any g-cqd or Aemi-Studio package, Apple/swiftlang ones on approval (ADR-0002 accepted, `TerminalKitText` added by revision pin); and GPU acceleration should be toggleable (ADR-0024 proposed: one renderer seam, CPU renderer as a product and oracle, `auto|gpu|cpu` at run time; the screen keeps per-row dirty bits for it).

Every stream allocates nothing.

## Replies and modes (ADR-0026)

This time a real red: tests against stubs (52 issues), then the implementation. One patch to the escape handler silently missed because swift-format indents `case` labels in this repo (the same lesson as TerminalUI: re-check that edits applied; a test caught it). Mutation run on the new code: one survivor (keyboard stack depth, my test pushed and popped equally), fixed. Refactor first: the loose mode booleans became one `Modes` value, behind a green suite.

## History and resize (ADR-0028)

Fast iteration, no local mutation sweeps (owner: leave them to CI). Tests first against stubs: the run crashed on an out-of-range history read, which is red but obscure; the implementation then made all but a few tests pass. The suite then **hung**: with a colourful history the style table filled, compaction could not free anything (the history alone needed more than 65 536 styles) and ran again on every new style. Fixed by bounding what a rebuild keeps (screens first, history newest first, three quarters at most) and by two tests that pin both outcomes. Three failures were my own wrong expectations (cursor past a line that exactly fills a row; the alternate screen's text written after 1049 without homing; trailing typed spaces in the property helper), fixed in the tests, each reasoned rather than bent to pass.

## Host and oracle (ADR-0030)

First time real programs ran in the emulator: vim and less work. The less layout (file at the bottom of the screen) looked wrong until kitty, fed the same bytes, drew the same: the program asks for it. Building the comparison script took more care than the PTY code (reading kitty's screen before it had finished drawing gave one false difference; kitty joins wrapped rows and keeps tab characters). All 15 streams then agree on text. The CI lesson stands: the comparison needs a GUI session, so it is a local probe, not a CI job.

## More oracles

Owner: "you could also use ghostty and alacritty", then "to close a ghostty window you need to kill the process first". The Ghostty adapter's first cleanup ran `kill` with pid 0 (Ghostty's "unknown") and took down its own process group; it now signals only a real pid on the right tty, and the window's program is a loop that ends on request so the window closes without a prompt. Alacritty's Homebrew cask is disabled, so it was built with cargo. A 27-query reply stream on four terminals showed Sunset agreeing with the majority everywhere except where it deliberately differs; two inconsistencies in my own replies were fixed. A history stream differed only because Ghostty's screen file includes scrollback.
