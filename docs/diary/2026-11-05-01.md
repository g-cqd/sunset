# Diary — 2026-11-05 (01)

## Setting up, and what was probed on day one

Owner direction: a Swift terminal, kitty-graphics compatible with every modern feature, macOS first and Linux a target; performance, safety, resilience, reliability, security; colour accuracy, GPU, typography; only our own tooling; name undecided.

| Claim | Probe | Verdict |
|---|---|---|
| A PTY with a controlling tty needs no `fork` from Swift | `openpty` + `posix_spawn(POSIX_SPAWN_SETSID)` + `dup2` file actions; child `sh -c 'tty; ps -o pid,tpgid,tty -p $$'` (macOS 27.0.1) | **CONFIRMED**: `/dev/ttys012`, `TPGID == PID`. Not probed: job control, SIGWINCH, login/utmp, Linux |
| swift-subprocess and swift-system offer a PTY | grep for openpty/forkpty/pseudo in shallow clones | **REFUTED**: none (one comment about a controlling pseudo-terminal signal) |
| `forkpty` is callable from Swift | compiled a call | **Compiles only**; not run; and `fork` in a multithreaded Swift process is unsafe, so not used |
| kitty cell layout (CPUCell 12 B, GPUCell 20 B) | `static_assert`s in `kitty/line.h` | **CONFIRMED by reading** |
| Ghostty's embeddable core is a C/Zig library | repo README (`libghostty`, "zero-dependency C and Zig library"); `include/ghostty` | **CONFIRMED by reading**; not built, not measured |
| SwiftTerm is a mature Swift emulator | shallow clone: ~75k lines, Terminal.swift 10.6k, kitty graphics/keyboard/clipboard files, vtebench ports | **CONFIRMED by reading**; quality and speed not measured |
| TerminalKit already has a DECRQM harness against four terminals | read roadmap 0002 and its done section | **CONFIRMED by reading**; not rerun |

## Kernel study probes and oracle installs (Apple M3, macOS 27.0.1, clang -Os)

| Claim | Probe | Verdict |
|---|---|---|
| Aemi's kernels are intrinsics, not assembly | `find -name '*.S'`, grep `asm` | **CONFIRMED**: no `.S`; inline asm in two files only (`adf_crypto_secure.c`, `adf_cpu_timing.c`) |
| The existing control-byte scan suits a VT parser's per-run use | `probes/vtscan.c` on five synthetic streams | **REFUTED for short runs**: 0.74–1.55 GB/s on SGR/TUI/ls-like streams vs 3.3–4.2 on long runs; a bulk positions kernel reaches 5.2–10.7 GB/s on all |
| Scanning is the terminal's bottleneck | compare 5–10 GB/s scan with kitty's published 60–250 MB/s end-to-end (vendor, other CPU) | **REFUTED (indirectly)**: scanning is ~2 orders of magnitude faster than end-to-end; the cell write path is the cost |
| A mismatch-index kernel beats the obvious loop and `memcmp` | `probes/cells.c` (b), after fixing a hoisting flaw in my first run | **CONFIRMED**: 37–54 GB/s vs scalar 17–19 and memcmp 31–34 (1.1–1.6x memcmp) |
| My first run of (b) was valid | constant 14 ns for every variant | **REFUTED**: loop-invariant call hoisted; fixed with a volatile function pointer and memory clobber |
| Structural encoding beats LZ4 of raw cells | `probes/lz.c`, 600 KB of Swift wrapped to 120 columns, synthetic styles | **CONFIRMED on this synthetic corpus**: 0.45 B/cell vs LZ4_RAW 0.82 (1.8x); real corpus not run |
| Platform LZ4_RAW baseline | same | 1.52 GB/s compress, 4.08 GB/s decompress |
| ghostty 1.4.0 and wezterm install via brew | `brew install --cask` | **CONFIRMED** |
| alacritty installs via brew | same | **REFUTED**: cask disabled 2026-09-01 (Gatekeeper); built from source instead, 0.18.0-dev, 1 m 30 s |
| Machine is an M2 Pro (as aemi ADR-0011 measured) | `machdep.cpu.brand_string` | **REFUTED**: Apple M3; no SME/SVE (`FEAT_SME: 0`) |
