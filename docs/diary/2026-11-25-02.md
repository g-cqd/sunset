# 2026-11-25 — 02: Update download indicator and flow fixed (`UpdateHTTPTransfer`, off-main staging, linear progress + failure UI)

| Claim | Probe | Verdict |
|---|---|---|
| `RangeDownloadDelegate` progress callbacks never fired on macOS | Standalone Swift probe calling `URLSession.data(for:delegate:)` and `URLSession.download(from:delegate:)` against GitHub's `v0.1.0-alpha.15` release assets | **Confirmed**: `redirects=1`, **`responses=0`, `dataCallbacks=0`** for both async overloads. On top of that, `RangeDownloadDelegate` did not even conform to `URLSessionDownloadDelegate`, so full `.zip` downloads could never report progress either. |
| Delegate-driven `URLSession.dataTask(with:)` and `downloadTask(with:)` fire incremental progress | Standalone Swift probe against GitHub's `v0.1.0-alpha.15` assets (`bytes=0-262143` and `release-index.json`) | **Confirmed**: `DataTaskRunner` fired 15 progress ticks for 256 KiB; `DownloadTaskRunner` fired `didWriteData` and moved the file cleanly. |
| `ProgressView(value: 0)` in Settings and the update window looked stuck and never animated | Read `UpdatesCenter`, `UpdateComponentRow`, `UpdateNotes`, `AppUpdates`, `UpdateTransfer` | Four compounding causes: (1) `downloadProgress` stayed pinned at `0` because of the `URLSession` async overload bug; (2) `ProgressView(value: 0)` with no `.progressViewStyle(.linear)` on macOS renders an empty static ring/bar with no spin; (3) `AppUpdates.download` ran `UpdateTransfer.stage` (LZMA decompression, `ditto` unzip, SHA-256 hashing, `codesign` verification) on `@MainActor`, blocking UI updates; (4) `UpdateNotes` had no `.failed` case in its footer/header/button, so a failed update silently reset to "Update" with no error message. |
| Fix: `UpdateHTTPTransfer` + detached staging + `UpdateProgressView` + failure UI in `UpdateNotes` | `UpdateHTTPTransferTests` (red first, then green); full `swift test`; Debug & Release builds; `.ci/swift-ci run quality`; clones | All tests pass (44 in `SunsetUpdateTests`), Debug + Release build cleanly, quality exit 0, clones 132. Not yet seen live on screen in the running app. |
