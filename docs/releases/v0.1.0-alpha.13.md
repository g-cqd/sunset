The thirteenth alpha of Sunset. One app now, with two ways to run the web: on macOS's WebKit, or on Sunset's own,
switched from Settings. Expect rough edges, and settings or saved state that a later build may not read.

**One app, two web engines.**
- **Sunset** (`Sunset-v0.1.0-alpha.13-…`): pages run on the system's WebKit, the one Safari uses, with its security
  updates from macOS. Most people want this.
- **Sunset with its own WebKit** (`Sunset-WebKit-v0.1.0-alpha.13-…`): the same app, `Sunset.app`, with WebKit's main branch
  at 944f9ff672 and 37 patches of ours inside it. It gets WebKit's security fixes only from a later Sunset, and says when
  its engine is eight weeks old.
- **Switching:** Settings › General › Updates › Web engine. Sunset downloads the other variant, checks it, and swaps itself
  at a restart. Going to Sunset's WebKit downloads about 47 MB; back to the system's, a few kilobytes.
- Each engine keeps its own website data (logins, storage), since a newer WebKit stores some of it in ways the system's
  cannot read. Switching back finds the first engine's data where it was left.

**If you use Sunset WebKit (the separate app, up to alpha.12).** It is retired. It will not update to this release: it
is another app to macOS. Install Sunset, then switch the web engine in Settings. Your Sunset WebKit data stays where it is,
untouched; it is not carried over.

**What changed since alpha.12.**
- **Updates.**
  - One update file per variant, read by byte range: Sunset fetches only the part made for the build it runs.
  - Each release carries an index signed with Sunset's own key; Sunset checks it before reading anything it downloads,
    and checks every piece against it. Downloads only come from GitHub, over HTTPS.
  - Then, as before, Apple's signature and notarization, our team, and a later build.
  - A download's progress is shown; a refusal says why, in a sentence.
  - Coming from alpha.12, Sunset downloads the whole app this once.
- **Sunset's WebKit runs without the loader exception** an audit flagged as critical, and its helper processes run under
  Sunset's own names.
- **Passwords.** Lock after a set time, on leaving the vault's tab, or when its window is no longer in front: each a
  setting under Privacy and security › Passwords. Edits are kept as you type, and before any lock.
- **Appearance.** Icon previews in Settings, and an Auto icon (the default) that follows the time of day; the welcome's
  sky follows it too.
- **Tabs and menus.** Every item of a tab's menu shows its symbol, in the menu's colour.
- **Fixed.** Passwords missing from a second window's Library.

**Install.** Unzip, move the app to Applications, open it. Both are signed with a Developer ID and notarised by Apple. They
need macOS 26 or later and a Mac with Apple silicon.

**Check the download.** `shasum -a 256 -c NAME.zip.sha256` in the folder holding both files.

**Known.** Setting up Passwords with Touch ID on can close the window that shows the recovery code a few seconds after it
appears: copy the code at once, or set up without Touch ID. Being fixed.

**Not in it yet.** Linux; Intel Macs; Sixel and iTerm2's images, kitty's animations; syncing the vault between Macs,
importing from other password managers; protected video on some sites (CNN); several pieces of the roadmap
(`docs/roadmap`, each entry says what is not done).

Report what breaks in the repository's issues.
